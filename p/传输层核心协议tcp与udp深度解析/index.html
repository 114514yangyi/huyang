传输层协议深度解析

套接字与端口机制

套接字(Socket)

套接字是操作系统提供的网络编程接口，充当应用进程与传输层之间的通信桥梁。它抽象了底层网络细节，为应用程序提供统一的网络访问方式。

传输层地址标识： 每个套接字由二元组 <主机IP地址, 端口号> 唯一标识，构成完整的传输层端点地址。

端口(Port)

端口是16位数字标识符（0-65535），用于区分同一主机上的不同应用程序：

  • 网络数据包头部包含源端口号和目的端口号
  • 网络设备依据端口号识别和路由到正确的应用程序
  • 知名端口：0-1023（如HTTP-80、HTTPS-443）
  • 注册端口：1024-49151
  • 动态端口：49152-65535

多路复用与分解机制

UDP协议特性

  1. 无连接协议：仅根据目的IP和端口进行报文分配
  2. 轻量级传输：无序列号、重传和流控制机制
  3. 尽力而为服务：不保证可靠交付
  4. 典型应用：DNS查询、流媒体、实时通信

校验和计算机制

将每16位作为加数求和（包括伪首部、UDP首部和数据），进位回加到个位，最后取反码作为校验和。

TCP协议特性

  1. 面向连接：基于四元组<源IP, 源端口, 目的IP, 目的端口>分配套接字
  2. 可靠传输：提供有序、可靠的字节流服务
  3. 流量控制：动态调整发送速率避免拥塞

关键字段详解：

  • 序列号(32位)：本报文段第一个字节的序号
  • 确认号(32位)：期望收到的下一个字节序号
  • 数据偏移(4位)：TCP首部长度（以4字节为单位）
  • 控制标志(6位)：
    • URG：紧急指针有效
    • ACK：确认字段有效
    • PSH：推送功能，立即交付
    • RST：连接复位
    • SYN：同步序列号，建立连接
    • FIN：终止连接
  • 窗口大小(16位)：接收窗口大小，用于流量控制
  • 校验和(16位)：首部和数据的校验和
  • 紧急指针(16位)：紧急数据末尾位置（URG=1时有效）

TCP连接管理

三次握手建立连接

  1. SYN发送（客户端→服务端）

    • 发送：SYN=1, Seq=ISN_A, ACK=0
    • 状态：CLIENT→SYN_SENT
    • 消耗一个序列号

  2. SYN-ACK响应（服务端→客户端）

    • 发送：SYN=1, ACK=1, Seq=ISN_B, Ack=ISN_A+1
    • 状态：SERVER→SYN_RECEIVED
    • 消耗一个序列号

  3. ACK确认（客户端→服务端）

    • 发送：ACK=1, Seq=ISN_A+1, Ack=ISN_B+1
    • 状态：双方→ESTABLISHED
    • 可携带数据，不消耗序列号

四次挥手释放连接

  1. FIN发送（主动方→被动方）

    • 发送：FIN=1, Seq=K
    • 状态：主动方→FIN_WAIT_1

  2. ACK确认（被动方→主动方）

    • 发送：ACK=1, Ack=K+1
    • 状态：被动方→CLOSE_WAIT
    • 主动方→FIN_WAIT_2

  3. FIN发送（被动方→主动方）

    • 发送：FIN=1, Seq=L
    • 状态：被动方→LAST_ACK

  4. ACK确认（主动方→被动方）

    • 发送：ACK=1, Ack=L+1
    • 状态：主动方→TIME_WAIT（2MSL）
    • 最终：双方→CLOSED

连接状态变迁

客户端状态流：CLOSED → SYN_SENT → ESTABLISHED → FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT → CLOSED

服务端状态流：CLOSED → LISTEN → SYN_RCVD → ESTABLISHED → CLOSE_WAIT → LAST_ACK → CLOSED

可靠数据传输机制

传输层与数据链路层对比

特性 传输层(TCP) 数据链路层
控制范围 端到端（进程间） 点到点（节点间）
窗口大小 动态可调整 固定大小
应用场景 网络层不可靠 物理链路可靠

注：TCP窗口大小通常按 $2^{10}$（1024）计算

传输错误类型及处理

  1. 比特错误：通过校验和检测，自动重传
  2. 分组丢失：超时重传机制保障
  3. 分组延迟：动态调整发送速率
  4. 分组乱序：序列号重新排序
  5. 分组重复：序列号检测丢弃

传输协议类型

停等协议（Stop-and-Wait）

  • 发送窗口=1，接收窗口=1
  • 每发送一帧等待确认后再发下一帧
  • 简单但效率低下

流水线传输（Pipelining）

  • 滑动窗口技术
  • 连续发送多个分组后再等待确认
  • 大大提高信道利用率

滑动窗口协议类型

GBN协议（回退N帧）

  • 发送方：窗口大小>1，累计确认
  • 接收方：窗口大小=1，按序接收
  • 重传策略：超时重传所有已发送未确认帧

SR协议（选择重传）

  • 发送方：为每个分组单独设置定时器
  • 接收方：窗口大小>1，可缓存乱序帧
  • 重传策略：仅重传丢失或错误的分组

TCP快速重传机制

当收到3个重复ACK时，推断分组丢失并立即重传：

  • 条件：连续收到4个相同ACK（1正常+3冗余）
  • 优势：避免等待超时，提高传输效率
  • 实现：接收方缓存乱序分组，发送方快速重传

超时时间计算

TCP使用自适应超时重传时间（RTO）计算：

EstimatedRTT = (1-α)×EstimatedRTT + α×SampleRTT
DevRTT = (1-β)×DevRTT + β×|SampleRTT - EstimatedRTT|
RTO = EstimatedRTT + 4×DevRTT

其中典型值：α=0.125, β=0.25

TCP流量与拥塞控制

流量控制（接收端主导）

防止发送方overrun接收方缓冲区：

  • RWND（接收窗口）：接收方空闲缓冲区大小
  • AWND（通告窗口）：接收方在ACK中通告的可用窗口
  • 发送窗口 = min(CWND, RWND)

滑动窗口机制：

  • 接收方通过ACK携带窗口通告信息
  • 发送方根据通告窗口调整发送速率

拥塞控制（发送端主导）

基于网络拥塞状况动态调整发送速率：

1. 慢启动（Slow Start）

  • 初始：CWND = 1 MSS
  • 每RTT：CWND倍增（每ACK：CWND += 1）
  • 终止条件：CWND ≥ ssthresh

2. 拥塞避免（AIMD）

  • 每RTT：CWND += 1 MSS（每ACK：CWND += 1/CWND）
  • 乘法减小：发生拥塞时 ssthresh = max(CWND/2, 2)

3. 快速恢复（与快速重传协同）

  • 收到3个重复ACK：ssthresh = CWND/2, CWND = ssthresh + 3
  • 每收到重复ACK：CWND += 1 MSS
  • 收到新数据ACK：CWND = ssthresh

TCP变种协议对比

协议类型 超时处理 重复ACK处理 特点
TCP-Tahoe CWND=1 CWND=1 基础版本，无快速恢复
TCP-Reno CWND=1 CWND=CWND/2 引入快速恢复
TCP-NewReno CWND=1 改进的快速恢复 增强恢复性能
TCP-SACK 选择性确认 选择性重传 高效处理多个丢包

可靠数据传输协议演进

RDT 1.0：理想信道

  • 假设：无差错、按序到达
  • 机制：简单发送-接收模型

RDT 2.0：比特差错信道

  • 新增：校验和检测、ACK/NACK反馈
  • 机制：出错重传

RDT 2.1/2.2：序列号机制

  • 新增：分组序列号（0/1交替）
  • 解决：ACK/NACK混淆问题

RDT 3.0：丢包信道

  • 新增：超时重传计时器
  • 机制：停等ARQ协议

容量单位规范

二进制基数（$2^{10}$ = 1024）

适用场景：

  • 计算机内存容量（RAM）
  • 文件存储大小
  • 网络协议字段（如TCP窗口大小）
  • 操作系统显示单位

标记方式：KiB、MiB、GiB（IEC标准）

十进制基数（$10^{3}$ = 1000）

适用场景：

  • 存储设备标称容量（HDD/SSD）
  • 网络带宽（bps）
  • 数据传输速率
  • 国际标准单位

标记方式：KB、MB、GB（SI标准）

实际应用注意

  • 存储设备：厂商使用十进制，系统使用二进制显示
  • 网络协议：带宽用十进制，数据量用二进制
  • 计算吞吐量时需明确单位基准

性能指标计算

吞吐量公式

$$ \text{吞吐量} = \frac{\text{传输数据量}}{\text{传输时间}} \leq \text{信道带宽} $$

有效载荷率

$$ \text{效率} = \frac{\text{MSS}}{\text{MSS + TCP头开销}} \times \text{带宽利用率} $$
