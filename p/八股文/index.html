线程与进程的区别及联系

线程与进程之间的区别和联系我可以从以下几个方面来阐述：

  1. 资源分配：进程是资源分配和调度的基本单位，每个进程都有独立的地址空间和系统资源；线程是程序执行的基本单位，同进程的多个线程共享进程的资源。

  2. 切换成本：线程切换只需要保存少量寄存器状态，切换速度快；进程切换需要切换整个地址空间，成本更高。

3）通信机制：进程间通信需要通过复杂的IPC机制；线程可以直接读写进程数据段进行通信。

  1. 稳定性：一个线程崩溃可能导致整个进程终止；进程之间相互独立，一个进程崩溃不会影响其他进程。

主要联系在于线程依附于进程存在，一个进程至少包含一个线程，多线程工作在同一进程地址空间内协同完成任务。它们都是操作系统实现并发的重要手段。

死锁条件

死锁 是指两个或多个进程/线程因竞争资源而 永久阻塞 的状态，所有参与方都无法继续执行。

  1. 资源互斥
  2. 持有并等待
  3. 不能夺取别人的资源
  4. 资源的持有并等待的关系成环

用户态和内核态概念,并且说明原因,怎么切换

  • 用户态：用户态是CPU运行用户程序的一种模式，权限较低，不能直接访问硬件资源；用户态需要通过系统调用（System Call）请求内核态的服务。
  • 内核态：内核态是CPU运行操作系统内核的一种模式，拥有最高权限，可以直接访问硬件资源；内核态负责管理系统的核心功能，如进程调度、内存管理、设备驱动等。

原因:

  1. 安全管理:

    用户态和内核态之间做了隔离,这样子话,用户的应用程序所导致的崩溃或者内存泄漏就不会影响到系统内核的崩溃

  2. 统一接口:

    内核态直接管理硬件资源,将硬件资源抽象称为许多可以通过systemcall来调用的统一接口,用户态的应用程序就可以直接调用统一的接口来获取资源和服务

  3. 权限控制:

    通过系统调用（syscall）实现 最小权限原则

切换:

  1. 系统调用
  2. 中断
  3. 异常

协程

协程是 用户态轻量级线程，由程序自身调度（而非操作系统），可在任意位置挂起/恢复，避免线程切换的开销。

Cache定义

Cache（缓存） 是一种用于存储临时数据的高速存储器，位于 CPU 和主存（RAM）之间，旨在减少数据访问延迟

  • 核心目标：解决 CPU 和主存之间的速度差距（Memory Wall 问题）。

软链接和硬链接之间的区别

  • 硬链接：
    • 本质是iNODE目录项的别名,指向同一个文件和inode目录项,并且将引用计数+1
    • 本质是同一个 inode 的多个目录项（dentry），ls -i 可看到 inode 号相同。
    • 引用计数（ls -l 的第二列数字）表示有多少硬链接指向该 inode。
    • 删除文件 = 减少引用计数，只有计数归零时数据块才被释放。
  • 软链接：
    • 本质上是所指文件的绝对路劲的别名,是使用另一个新的文件去存储所指文件的绝对路劲,拥有不同的inode号,对引用计数不产生影响.
    • 是一个独立的小文件（有自己的 inode），内容存储目标文件的绝对/相对路径。
    • 类似 C 语言的指针，解引用时需逐层查找（可嵌套，如 A→B→C）。

大端序和小端序

区别本质：数据在内存中的字节存储顺序不同

大端存储是高位字节存储在低地址中,小端存储是低字节在低地址中.

大端序更适合的场景

场景 原因
网络协议（TCP/IP） RFC标准强制要求，保证跨平台一致性
加密算法（如AES） 部分算法设计中高位优先处理更高效
Java虚拟机（JVM） 语言规范规定大端序，确保跨平台行为一致
嵌入式系统（如汽车ECU） 传统行业协议（CAN总线）常用大端序

✅ 小端序更适合的场景

场景 原因
x86/x64 CPU架构 Intel/AMD 长期使用，硬件优化深入
Windows/Linux系统 基于x86架构原生支持
内存敏感型操作 类型转换时无需调整指针（如 float* 转 int*）
ARM移动设备（默认） 现代ARM默认小端序，Android/iOS均适配

CPU100%？怎么定位？

使用top或者htop命令来查看占用CPU异常的一些进程,然后对于这个进行使用kill pID来防止CPU占用过大.

一般CPU100%就是因为像发生了死循环,锁的竞争,大量的系统调用.

什么是孤儿进程和僵尸进程，如何处理它们？

孤儿进程就是子进程的父进程已经停止运行,但是子进程仍然保持运行状态,此时会有init进程接管这个孤儿进程,并且init进程会定时调用wait或者waitpid来获取子进程的退出状态.

僵尸进程就是子进程已经停止运行了,但是父进程并且回收子进程的退出状态,从而导致子进程的进程表PCB任然没有办法进行回收,从而占用系统的资源,占用PID的数量.

fork知道吗，fork返回的值是什么

fork返回值主要和经过fork以后程序是父进程还是和子进程有关,对于子进程而言,fork的返回值是0,但是对于父进程而言,fork的返回值是子进程的processid;并且假如fork因为像内存不够等原因导致fork失败的话,就会返回-1;

浏览器键入网址全过程

当你在浏览器输入网址（如 https://www.example.com）并按下回车后，浏览器会执行一系列复杂的网络请求和渲染操作，最终显示网页内容。以下是详细的处理流程：

1. 浏览器解析 URL

  • 检查 URL 格式，识别协议（http/https）、域名（www.example.com）、路径（/）、查询参数（?key=value）等。
  • 如果输入非完整 URL（如 example.com），浏览器会自动补全协议（https://）和路径（/）。

2. 检查缓存

浏览器会按顺序检查缓存，决定是否直接返回本地资源：

  1. 浏览器缓存（Cache-Control/Expires）
    • 如果有未过期的缓存，直接显示页面（200 OK (from disk cache)）。
  2. Service Worker 缓存（PWA 离线缓存）
    • 若注册了 Service Worker，可能拦截请求并返回缓存。
  3. DNS 缓存
    • 检查本地是否有域名的 DNS 缓存（省去 DNS 查询）。

3. DNS 解析（域名 → IP）

如果域名未缓存，浏览器触发 DNS 查询：

  1. 本地 DNS 缓存（操作系统、路由器、浏览器缓存）。
  2. 本地 DNS 服务器（如 ISP 提供的 8.8.8.8）。
  3. 递归查询（从根域名→顶级域名→权威 DNS 服务器）：
    • 根域名服务器（.） → .com 服务器 → example.com 的权威 DNS 服务器。
  4. 返回 IP 地址（如 93.184.216.34），并缓存结果。

4. 建立 TCP 连接（三次握手）

获取 IP 后，浏览器通过 TCP/IP 协议 与服务器建立可靠连接：

  1. SYN → 客户端发送同步请求（Seq=x）。
  2. SYN-ACK → 服务器确认并回应（Seq=y, Ack=x+1）。
  3. ACK → 客户端确认（Ack=y+1），连接建立。 ✅ 如果是 HTTPS，还会进行 TLS 握手（见下一步）。

5. TLS 握手（HTTPS 安全连接）

HTTPS 在 TCP 基础上增加 加密层（TLS/SSL）：

  1. Client Hello → 客户端支持的加密算法 + 随机数。
  2. Server Hello → 服务器选定的加密算法 + 随机数 + 证书（含公钥）。
  3. 验证证书：浏览器检查证书是否过期、是否受信任（CA 签发）。
  4. 密钥交换：客户端生成预主密钥，用公钥加密后传给服务器。
  5. 生成会话密钥：双方用随机数 + 预主密钥生成对称加密密钥。
  6. 加密通信开始：后续数据传输使用对称加密（如 AES）。

6. 发送 HTTP 请求

建立连接后，浏览器发送 HTTP 请求：

  1. 静态资源（如 HTML/CSS/JS）：直接返回文件。

  2. 动态资源（如 PHP/Node.js）：交给后端程序处理，生成 HTML。

8. 浏览器渲染页面

收到响应后，浏览器开始解析和渲染：

  1. 解析 HTML → 构建 DOM 树。
  2. 解析 CSS → 构建 CSSOM 树。
  3. 合并 DOM + CSSOM → 生成 渲染树（Render Tree）。
  4. 布局（Layout） → 计算元素大小和位置。
  5. 绘制（Paint） → 将像素绘制到屏幕。
  6. 执行 JavaScript：
    • 遇到 <script> 会阻塞渲染（除非加 async/defer）。
    • 可能触发重新布局（Reflow）和重绘（Repaint）。

http为什么是无状态

  1. 设计初衷 HTTP 最初用于简单的文档请求（如 HTML 文件），每个请求只需返回对应资源，无需记录上下文。这种设计：
    • 降低服务器负担：不存储客户端状态，节省内存和 CPU。
    • 提高可扩展性：服务器能轻松处理高并发请求，无需跟踪用户会话。
  2. 协议本身无记忆能力 HTTP 的请求和响应的报文格式（Header + Body）不包含任何历史请求的上下文信息。

说说TCP和UDP有什么差异，有什么应用场景

  • TCP:

    拥有一系列的可靠传输机制,比如说向ACK确认,超时重传,顺序传输,拥塞控制,流量控制等机制+拥有连接管理,有三次握手和四次挥手+有连接的协议

    传输文件时若丢包，TCP 会自动重发丢失的分片。

  • UDP:

    没有可靠传输机制+没有连接管理+是无连接的协议

    示例：视频通话中丢失少量帧不影响整体观看，但重传反而会导致延迟。

TCP怎么保证数据可靠传输的

三次握手+四次挥手+ACK确认机制+超时重传+数据分片\序列号+差错检验+拥塞控制+流量控制+快速重传+快速回复

TCP3次握手和4次挥手的流程

  1. 第一次握手（SYN）：
    • 客户端发送 SYN=1（同步位）并携带随机初始序列号 seq=J。
    • 内核动作：客户端进入 SYN_SENT 状态。
  2. 第二次握手（SYN+ACK）：
    • 服务端返回 SYN=1 和 ACK=1（确认位），携带自己的初始序列号 seq=K，并确认客户端序列号 ack=J+1。
    • 内核动作：服务端进入 SYN_RCVD 状态，分配连接资源（如缓冲区）。
  3. 第三次握手（ACK）：
    • 客户端确认服务端的序列号 ack=K+1，此时可携带应用层数据。
    • 内核动作：双方进入 ESTABLISHED 状态。

为什么是三次握手？

  • 防止历史连接干扰：若旧的重复 SYN（J）到达服务端，客户端通过第三次握手可拒绝（回复 RST）。
  • 资源节约：两次握手时，服务端会因未确认的 SYN 请求浪费资源（SYN Flood 攻击利用此缺陷）

三次握手的目的，是为了防止A端已经失效的连接请求突然又传到B端，被误认为是A端再次发出的一个新的连接请求，如果B端这时又再次向A发出确认报文，表示同意建立连接，就会产生错误。

关键步骤解析

  1. 第一次挥手（FIN）：

    • 主动关闭方（如客户端）发送 FIN=1 和序列号 seq=u。
    • 内核动作：客户端进入 FIN_WAIT_1 状态。

  2. 第二次挥手（ACK）：

    • 被动关闭方（如服务端）返回 ACK=1 确认 ack=u+1。

    • 内核动作

      ：

      • 客户端进入 FIN_WAIT_2 状态。
      • 服务端进入 CLOSE_WAIT 状态，仍可发送残留数据。

  3. 第三次挥手（FIN）：

    • 服务端发送自己的 FIN=1 和序列号 seq=v，确认号仍为 ack=u+1。
    • 内核动作：服务端进入 LAST_ACK 状态。

  4. 第四次挥手（ACK）：

    • 客户端确认服务端的 FIN 包 ack=v+1。

    • 内核动作

      ：

      • 服务端立即进入 CLOSED 状态。
      • 客户端进入 TIME_WAIT 状态，等待 2MSL（Maximum Segment Lifetime）。

为什么需要四次挥手？

  • 全双工特性：TCP 连接是双向独立通道，需分别关闭发送和接收方向。
  • 延迟关闭：被动方可能仍有数据发送（第二次挥手后），需等待数据传输完成再发 FIN。

TIME_WAIT 状态的必要性

  • 等待时间

    ：通常 2MSL（Linux 默认 60秒），作用：

    1. 确保最后一个 ACK 到达对方（若丢失，被动方会重传 FIN）。
    2. 让网络中残留的旧报文失效，避免影响新连接。

  • 副作用：高并发短连接场景下可能导致端口耗尽（可通过 SO_REUSEADDR 参数优化）。

为什么time_wait是2MSL为什么不是1MSL，为什么不是3MSL

因为使用2MSL时间就已经够用了,其中MSL的定义是一个报文能够在互联网络中存活的最大时间.

而等待了2MSL时间以后就能够确保服务器端能够接收到最后的ACK确认,因为假如最后没有接收到的话,在2MSL时间内服务器就会重传FIN包;

其次呢等待2MSL时间可以彻底的清除在网络中所有旧的数据包,避免旧的数据包影响到之后建立新的连接.

这个之所以所以不使用1MSL的等待时间是因为客户端发送ACK包可能会在网络中消耗1MSL的时间,而服务器端在重传FIN包,也会有可能在网络中逗留1MSL时间,因此这里假如只有等待1MSL的时间的话,就有可能会导致我客户端发送的ACK包在消耗掉1MSL时间,客户端误以为服务器端已经接收到了ACK包而关闭连接,但是此时服务器端在重传FIN包就会导致旧的数据包影响到了新的连接的建立了,所以只使用1MSL时间是不够的.

而不使用3MSL时间是因为等待2MSL时间是已经能够避免上述的情况的,因此不需要等待更长的时间.

DNS怎么查询的

客户端 → 本地 DNS 解析器（递归查询）

  • 客户端向本地 DNS（如 8.8.8.8）发起请求： Query: “请问 www.example.com 的 IP 是多少？”
  • 若缓存中有记录：直接返回结果（TTL 未过期）。
  • 若无缓存：本地 DNS 开始迭代查询。

2. 本地 DNS → 根域名服务器（.）

  • 根服务器不直接回答查询，而是返回顶级域的线索： Response: “我不知道 www.example.com，但你问 .com 的服务器（如 a.gtld-servers.net）吧，它的地址是 192.5.6.30”

3. 本地 DNS → .com TLD 服务器

  • TLD 服务器返回二级域的权威服务器地址： Response: “去问 example.com 的权威服务器吧（如 ns1.example.com），它的地址是 203.0.113.1”

4. 本地 DNS → 权威服务器（example.com）

  • 权威服务器返回最终答案： Response: “www.example.com 的 IP 是 93.184.216.34”

5. 本地 DNS → 客户端

  • 本地 DNS 缓存结果并返回给客户端： Final Answer: "www.example.com = 93.184.216.34"

MySQL 如何实现分页（如limit m,n的用法）

MySQL 的分页主要通过 LIMIT offset, size（或 LIMIT size OFFSET offset）实现，其中 offset 指定跳过多少行（默认0），size 指定返回的行数；例如 LIMIT 10, 20 表示跳过10行后取20行数据，但深分页（如 LIMIT 100000, 10）会扫描大量无效数据导致性能下降，优化方法包括使用覆盖索引、延迟关联（先通过子查询定位主键再关联）或记录上一页的边界值（如 WHERE id > 100000 LIMIT 10）。

当数据量超大时，limit m,n的执行过程及性能问题（如越往后分页越慢的原因）

在 MySQL 中，LIMIT m, n 的执行过程是 先扫描前 m + n 条数据并丢弃前 m 条，即使最终只返回 n 条数据，当 m（偏移量）非常大时（如 LIMIT 1000000, 10），数据库仍要完整读取 1000010 行但最终抛弃前 1000000 行，导致 CPU、IO 开销剧增，同时可能导致 临时表或文件排序（如果未走索引排序），优化方式包括：（1）用覆盖索引 + 延迟关联（如 SELECT * FROM t JOIN (SELECT id FROM t ORDER BY key LIMIT 1000000, 10) AS tmp ON t.id=tmp.id）；（2）使用基于有序游标的分页（如 WHERE id > 1000000 ORDER BY id LIMIT 10）避免全量扫描。

B数和B + 树的特点,好处

B树是一种多路平衡搜索树，其特点是每个节点可以存储多个键值，并且所有叶子节点位于同一层，好处是能够减少磁盘I/O次数，适合在内存有限时高效查找数据，但由于节点既存储数据又存储键值，范围查询效率较低；而B+树在B树基础上优化，特点是非叶子节点只存键值不存数据（数据全部集中在叶子节点），且叶子节点通过指针连接成有序链表，这使得B+树比B树更加矮胖（树高度更低，减少I/O），范围查询更高效（只需遍历链表），同时更适合磁盘存储（节点结构简单，能存储更多键），因此MySQL等数据库的索引一般使用B+树而非B树。

高扇出,低扇入.

为什么使用B+树,而不使用其他的数据结构

对于一帮的快速查询的数据结构有哈希表,二叉排序树,平衡二叉树,红黑树;

对于哈希表来说,他的查询速度是O(1),查询很快,但是不能够支持范围查询;二叉排序树的插入和查询是O(logn),其中左边的节点小于当前节点,右边的节点大于当前节点,因此可以进行范围查询,也可以进行排序,但是在ID自增键这样子的插入情况下,很容易退化成为链表,时间复杂度退化成为O(n)成为全表遍历;而对于平衡二叉树来说,他对于树的节点使用一系列的旋转操作保证了每一个左右子树的高度差最大为1,从而保持了树的平衡,但是他的维持平衡的旋转操作开销太大,对于一些颠簸的插入删除操作就会频繁进行旋转,需要维持绝对的平衡,对应到数据库中,频繁地旋转就会带来大量的磁盘IO;对于红黑树来说是使用将节点染色称为红色和黑色和旋转操作来维持树的平衡的,

联合索引在 B + 树上的存储方式（如何按索引顺序构建树结构）

在 B+ 树中，联合索引（复合索引）的存储方式 遵循 “最左匹配原则"，其特点如下：

  1. 键值排序规则

    • 联合索引 (a, b, c) 在 B+ 树上存储时，会先按 a 排序，如果 a 相同，则按 b 排序，若 a 和 b 都相同，再按 c 排序。
    • 【示例】(name, age, salary) 会先按 name 排序，再按 age 和 salary 逐级细化。

  2. B+ 树结构

    • 非叶子节点（中间层）仅存储索引列（如 (a,b,c)），不存储完整数据（减少 I/O）。
    • 叶子节点 以索引顺序排列，同时存储主键（聚簇索引）或完整记录（非聚簇索引），并按照 (a,b,c) 组织（如 (Alice,25,5000) 排在 (Bob,30,6000) 之前）。

  3. 查找方式

    • 如果查询含最左前缀（如 WHERE a=1 AND b=2），B+ 树可快速定位，因为数据已按 (a,b,c) 排序。
    • 如果跳过最左列（如 WHERE b=2），则失效（必须全表扫描），因为 b 本身不是独立的索引顺序。

优化点

  • 索引覆盖：若查询仅涉及 a,b,c，则可直接在索引层返回数据（无需回表）。
  • 顺序存储：范围查询（如 a>1 AND a<10）能高效执行（叶子节点链表遍历）。

什么是回表查询

假设你要根据name字段来搜索数据，比如：select * from user where name=‘xxx’，过程与主键索引一样的。从name索引的根节点开始找，一层一层的向下找，一直找到叶子节点，定位到name字段值对应的主键值。

但此时叶子节点的数据页没有完整所有字段，就需要根据主键到主键索引里去查找，从主键索引的根节点一路找到叶子节点，就可以找到这行数据的所有字段了，这个过程就叫回表。

索引

我们可以使用字典来进行一个比喻,在我们查询字典的时候,我们回首先查询字典的目录,然后通过目录迅速查找到我们想要的内容,而索引呢就是相当于字典里面的目录,他是一种可以快速帮助我们查找数据的数据结构,是利用空间换时间的思想,像字典一页一页地查询就是相当于全表扫描,而使用目录去查找数据就是相当于使用索引,使用索引就可以加速SQL的执行

分析索引失效的场景及失效后的查询结果

  1. 违反最左前缀匹配原则（联合索引失效）,查询的条件中并不涉及索引,或者涉及的联合索引并不符合最左前缀匹配
  2. 对索引列做了计算、函数或类型转换
  3. 用 !=、NOT IN、IS NULL、IS NOT NULL,或者是对于OR条件两边一边使用了索引列,一边使用了非索引列
  4. 模糊查询 LIKE '%xx'（前缀模糊匹配）
  5. 优化器放弃索引 数据量极少或索引区分度低
  6. 低选择性的字段做为索引的字段.
  • 查询仍然是正确的，不会因为索引失效而返回错误数据。
  • 但查询速度变慢，甚至可能从毫秒级降到秒级（取决于表数据量）。
  • 可以使用mysql的慢查询日志进行查看
  • 使用explain指令查询使用了什么索引,怎么走的索引

怎么充分利用索引

  1. 多使用联合索引,来达到覆盖索引的效果,防止回表
  2. 对于区分度高的字段建立索引
  3. 对于多次重复进行查询的字段建立索引
  4. 注意最左前缀匹配字段.

﻿事务的隔离级别

脏读:指读到了其他事务未提交的数据.

不可重复读:在同一个事务范围内多次读取同一个记录读出来不同的结果(update).

幻读:在同一个事务范围内进行范围查询读到了不同大小的结果集

未提交读(READ UNCOMMITTED):是最低的隔离级别,在这种隔离级别下,如果一个事务已经开始写数据,则另外一个事务则不允许同时进行写操作,但允许其他事务读此行数据。

已提交读:读取数据的事务允许其他事务继续访问该行数据,但是未提交的写事务将会禁止其他事务访问该行,会对该写锁一直保持直到到事务提交

可重读读:它是InnoDb的默认隔离级别,主要就是在一个事务的执行范围内对同一条记录的多次读取的结果是一致的,他的实现是使用MVCC的多版本控制来实现的,主要就是对于每一个语句都是建立记录的快照,并且记录每一个快照的版本号,比如说像什么时候创建的版本号,快照结束的版本号.

数据库的事务是什么概念？

事务是一种保证数据库系统一致性的核心机制,是通过将数据库中一系列操作原子化来实现的.实现一组不可分割的数据库操作序列

悲观锁和乐观锁

悲观锁是假设了事务对于共享资源和数据的访问存在着高亮的并发冲突,因此在对数据进行操作之前先尝试对于数据锁的获取,适合高并发冲突和强一致性场景;而对于乐观锁而言,是假设在并发冲突不高,读多写少的情况下,让事务直接去操作或者访问数据和共享资源,而在提交阶段去检查是否发生了冲突,假如发生了就是用版本号等机制去回退,适合读多写少和几乎不发生冲突的场景.

MVCC

使用多版本的方式,使得所有对数据库数据的修改都不会覆盖原有的数据,而是创建一个新的版本,通史保留旧版本的数据快照,因此可以实现读操作访问以前版本的数据快照,而读写操作不会相互阻塞,对于读多写少的场景提高了并发性能

他的主要实现就是对于每一行的数据都维持一个创建的事务ID和销毁的事务ID,在事务的处理过程中会依据当前read view来选择相应的数据快照版本.

MVCC的具体实现呢就是undo log加readview实现的.

ACID特性

A:原子性,保证了事务中一系列对于数据库的操作是不可分割的,也就是all or nothing ,里面的一系列的操作要么是成功完成提交的,要么是没有做的.

C:一致性,他表明数据库只能从某一个一致性的状态转换到另一个一致性的状态,而不会破坏数据库的约束条件等

I:是隔离性,他说明在事务并发处理的情况下,事务之间是相互隔离不受彼此影响的,一个事务的崩溃并不会导致其他事务的错误

D:持久性,党事务一旦提交,那么就会永久的保存在数据库的非遗实行的磁盘上,在后续系统故障中也不会丢失.

B+树页分裂

==插入:==

1）若为空树，创建一个叶子结点，然后将记录插入其中，此时这个叶子结点也是根结点，插入操作结束。

2）针对叶子类型结点：根据key值找到叶子结点，向这个叶子结点插入记录。插入后，若当前结点key的个数小于等于m-1，则插入结束。否则将这个叶子结点分裂成左右两个叶子结点，左叶子结点包含前m/2个记录，右结点包含剩下的记录，将第m/2+1个记录的key进位到父结点中（父结点一定是索引类型结点），进位到父结点的key左孩子指针向左结点,右孩子指针向右结点。将当前结点的指针指向父结点，然后执行第3步。

3）针对索引类型结点：若当前结点key的个数小于等于m-1，则插入结束。否则，将这个索引类型结点分裂成两个索引结点，左索引结点包含前(m-1)/2个key，右结点包含m-(m-1)/2个key，将第m/2个key进位到父结点中，进位到父结点的key左孩子指向左结点, 进位到父结点的key右孩子指向右结点。将当前结点的指针指向父结点，然后重复第3步。

==删除:== 2.3 B+树的删除操作

如果叶子结点中没有相应的key，则删除失败。否则执行下面的步骤

1）删除叶子结点中对应的key。删除后若结点的key的个数大于等于Math.ceil(m-1)/2 – 1，删除操作结束,否则执行第2步。

2）若兄弟结点key有富余（大于Math.ceil(m-1)/2 – 1），向兄弟结点借一个记录，同时用借到的key替换父结（指当前结点和兄弟结点共同的父结点）点中的key，删除结束。否则执行第3步。

3）若兄弟结点中没有富余的key,则当前结点和兄弟结点合并成一个新的叶子结点，并删除父结点中的key（父结点中的这个key两边的孩子指针就变成了一个指针，正好指向这个新的叶子结点），将当前结点指向父结点（必为索引结点），执行第4步（第4步以后的操作和B树就完全一样了，主要是为了更新索引结点）。

4）若索引结点的key的个数大于等于Math.ceil(m-1)/2 – 1，则删除操作结束。否则执行第5步

5）若兄弟结点有富余，父结点key下移，兄弟结点key上移，删除结束。否则执行第6步

6）当前结点和兄弟结点及父结点下移key合并成一个新的结点。将当前结点指向父结点，重复第4步。

注意，通过B+树的删除操作后，索引结点中存在的key，不一定在叶子结点中存在对应的记录。

==什么时候使用B+树索引:==

  • 可以直接使用索引而不是用表

数据库范式

  1. 第一范式（1NF）：要求数据表中的每个字段只能包含原子值。
  2. 第二范式（2NF）：要求满足 1NF，并且所有非主属性完全依赖于主键。
  3. 第三范式（3NF）：要求满足 2NF，并且每个非主属性直接依赖于主键，而不通过其他非主属性间接依赖。
  4. BCNF范式:在满足了3NF范式以后,还需要满足对于所有的非平凡依赖X->Y,都存在者X一定是某一个候选码.

C++

C++三大特性

C++的三大特性是分装,继承,多态;

其中分装表示的是在C++类中将数据和对于数据的操作分装起来,从而影藏内部的实现细节,相外界提供对应的接口.

而继承就是允许基于原有类来创建新的类,并且继承其中的一写成员函数或者是成员变量,并且可以扩展和自定义自己的属性和方法.

多态指的是允许同一个接口在运行时不同的情况下表现出不同的行为,一般是允许基类指针或者引用来操作派生类.

多态实现

C++中的多态主要是通过类中的虚函数来实现的,在基类中声明和定义了虚函数,在派生类中会对这些继承下来的虚函数进行重写,在基类指针或者引用指向的派生类调用虚函数的时候.运行时刻会动态绑定到相应派生类虚函数上.他实现的机制是在每一个有虚函数的C++类中都存在一个虚函数表virtual table,对于类的对象都存在一个虚指针,虚指针指向不同的虚函数表.在运行时刻会调用具体对象的虚函数表中的函数指针来实现动态绑定.

浅拷贝和深拷贝

浅拷贝和深拷贝之间的区别是对于对象成员内存复制的方式的不同;对于浅拷贝来说,他只是复制了像类中指针成员的值,而并没有复制指针所指对象的内存,因此对于新旧对象指针成员仍然指向同一片内存地址,这个很容易导致内存泄漏或者是重复释放的问题;而对于深拷贝来说,他是对于指针成员所指的对象申请不同的空间,进行拷贝,和之前的对象所指的内存空间不同,是完全独立的,而实现深拷贝就需要自定义拷贝构造函数,赋值操作符函数,析构函数来实现.

C++类型转换

C++中的强制类型转换是static_cast,dynamic_cast,reinterpre_cast,const_cast

static_cast是没有运行时类型检查的安全性的,并且他在进行上行类型转换的时候,是安全的;但是对于下行的类型转换是不安全的,因为没有动态的类型检查.

dynamic_cast在下行的类型转换是安全的,因为他有类型检查的功能,并且他在类型转换后一定是类的指针或者引用,其中基类中需要存在虚函数.他只能用于那些在基类派生类父子关系中有虚函数的强制类型转换,对于指针来说类型转换失败是直接返回nullptr,而对于引用来说是报错.

对于reinterpre_cast转换来说是可以将指针转换为数组,将整型转换成指针,可以在指针和引用中相互转换.

const_cast是将原来的常亮指针转换为非常量指针,将常量引用转换为非常量引用的,并且会去掉原有常量的static和volitile修饰的.

new和 malloc的区别

  1. new在分配内存空间失败的时候会直接抛出bad_alloc异常的;而malloc是直接返回nullptr
  2. new在分配内存空间的时候会自动计算对象的所需内存空间;但是像malloc是需要手动去申请额你存空间大小的
  3. new在申请内存空间的时候会调用类中的构造函数的;而malloc是不会的;
  4. new是可以做为operator操作符在类中进行重构的;而malloc只是一个函数,并不会进行这些操作;
  5. new是在自由存储空间中进行分配内存的;而malloc是在堆中进行分配的

placement new

是C++中的一种特殊的new操作,他是直接在已经分配好的内存上来构造新的对象的,而不用分配新的内存;通常它是用于一些高性能或者是内存管理的场景的.

在使用placement new的时候会直接调用对象的构造函数的,而不是像普通的new一样先调用operator new来分配内存空间的.

智能指针

智能指针 是一种自动管理动态内存的工具类，用于防止内存泄漏。

C++中提供了三种智能指针:unique_ptr,shareed_ptr,weak_ptr.

其中unique_ptr是有对资源的独占所有权的,在unique_ptr所指向的对象只会有一个unique_ptr指向的指针,并且unique_pre是不会进行拷贝复制的,只能进行移动;

shared_ptr是共享所有权的,可以有多个指针指向同一个对象的,背后实现的原理是维持一个对于对象的引用计数,当一个新的shared_ptr进行复制的之后,引用计数就加一,当对象进行销毁的时候,引用计数就减一,当引用计数为0的时候就自动回收对象的内存资源.

而weak_ptr是一种弱指针,他并不占有资源,适用于观察共享指针内存分配情况的,并且防止了shared_ptr的循环引用问题,weak_ptr并不会增加或者减少shared_ptr的引用计数,当引用计数为0的时候,对象销毁也不会对于weak_ptr产生影响.

在智能指针背后所运用的原理是RAII的思想,他是一种C++的资源管理的思想,简单来说就是:”我要对于我申请的资源负责到底,并且在我走的时候顺手将资源销毁”

shared_ptr是线程安全的吗？Sizeof(shared_ptr)是多少（32位机器）？

shared_ptr本身的引用计数是automic的,是线程安全的,但是其中指向的对象并不是线程安全的,并且对于shared_ptr的赋值等也是线程不安全的.

shared_ptr是有8个字节的,其中4个字节指向原始的对象内存地址的,剩下的四个字节只指向shaed_ptr的控制块,其中包含有引用计数等信息

volatile解决了什么问题

volatile实际上是一种和const绝对相反的修饰,使用volatile关键字修饰的变量其实是在告诉编译器,我这个变量的值极有可能发生修改,因此就是提示编译器所有和这个变量有关的运算都不要进行编译器的优化,并且这个变量值的获取灭磁都要从内存中读取,而不是从寄存器或者L1,L2cache中读取.

为什么拷贝构造函数的参数必须是引用？

如果参数是值传递（Person(Person obj)），会触发无限递归拷贝： 调用拷贝构造函数需先拷贝实参，而拷贝实参又要调用拷贝构造函数……最终栈溢出

如果参数是指针的话,那么就不会触发编译器的构造函数的签名,因为此时这个构造函数已经退化成为了一个普通的函数,里面传递的参数是指针,和编译器要求的引用不符合

设计模式

单例模式

单例模式是在程序的运行阶段,一个类只有一个实例的模式;

他的实现方法通常是在类中使用一个static的类实例的指针,然后在请求类实例的时候就返回这个实例的指针

有线程不安全的实现方式,就是在请求类实例的时候首先判断实例指针是否为nullptr,是的话就new一个示例给这个static的实例指针;

而线程安全的方式有直接在程序开始运行的阶段就直接对实例指针进行初始化;

也可以每次在获得实例的时候就加一个mutex_lock来避免冲突

或者使用双重检查来避免加锁的性能消耗,就是进程首先判断实例指针是否为null,为null就加锁,然后双重检查实例指针还是否为null,此时就可以给实例指针new一个新的对象.

1. 归并排序（Merge Sort）

基本思想

void merge(vector<int>& arr, int l, int m, int r) {
    vector<int> temp(r - l + 1);
    int i = l, j = m + 1, k = 0;
  
    // 合并两个有序子数组
    while (i <= m && j <= r) {
        if (arr[i] <= arr[j]) temp[k++] = arr[i++];
        else temp[k++] = arr[j++];
    }
    while (i <= m) temp[k++] = arr[i++];
    while (j <= r) temp[k++] = arr[j++];
  
    // 拷贝回原数组
    for (int x = 0; x < k; x++) {
        arr[l + x] = temp[x];
    }
}

void mergeSort(vector<int>& arr, int l, int r) {
    if (l < r) {
        int m = l + (r - l) / 2;
        mergeSort(arr, l, m);      // 左半部分递归
        mergeSort(arr, m + 1, r);  // 右半部分递归
        merge(arr, l, m, r);       // 合并
    }
}

应用场景

  • 外部排序（大数据量，如磁盘文件排序）。
  • 链表排序（合并时无需随机访问）。

2. 快速排序（Quick Sort）

基本思想

  • 分治法：选取一个基准（Pivot），将数组分为两部分（小于基准和大于基准），递归排序。

  • 最差（选最左/右为基准且数组已有序）：O(n²)
  • 空间复杂度：O(log n)（递归栈）

int partition(vector<int>& arr, int l, int r) {
    int pivot = arr[r];  // 选最右元素为基准
    int i = l;           // 标记小于 pivot 的边界
  
    for (int j = l; j < r; j++) {
        if (arr[j] < pivot) {
            swap(arr[i], arr[j]);
            i++;
        }
    }
    swap(arr[i], arr[r]);  // 将基准放到正确位置
    return i;
}

void quickSort(vector<int>& arr, int l, int r) {
    if (l < r) {
        int p = partition(arr, l, r);
        quickSort(arr, l, p - 1);
        quickSort(arr, p + 1, r);
    }
}

优化策略

  • 随机化基准：避免最坏情况（如 swap(arr[l], arr[rand() % (r - l + 1) + l])）。
  • 三数取中法：选左、中、右的中位数作为基准。

应用场景

  • 内核排序（如 C++ std::sort 的底层实现）。
  • 内存受限系统（原地排序，空间效率高）。

void bubbleSort(vector<int>& arr) {
    int n = arr.size();
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(arr[j], arr[j + 1]);
                swapped = true;
            }
        }
        if (!swapped) break;  // 本轮无交换则已有序
    }
}

应用场景

  • 教学示范（简单易懂）。
  • 小规模数据（或已接近有序的数据）。

5. 面试常见问题

Q：为什么 Quick Sort 比 Merge Sort 更常用？

  • 缓存友好性：Quick Sort 是原地排序（无需额外空间），访问内存更连续。
  • 常数因子更小：实际运行速度通常更快（尽管时间复杂度相同）。

Q：如何优化 Quick Sort 的最坏情况？

  1. 随机化基准：避免固定选最左/右元素。
  2. 三数取中法：选左、中、右的中位数作为基准。
  3. 切换到插入排序：对小规模子数组（如 n < 10）用插入排序。

quick sort能不能不使用递归实现

  1. 用栈保存待处理的子数组边界（left 和 right）。
  2. 循环处理栈中的区间，每次取出一个区间进行分区（Partition）。
  3. 将新生成的子区间压入栈中，直到栈为空
